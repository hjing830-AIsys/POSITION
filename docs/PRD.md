# POSTITON OL 产品需求文档（PRD）

| 项目 | 说明 |
| --- | --- |
| 产品名称 | POSTITON OL |
| 版本 | HTML 主页版（`index.html`） |
| 文档状态 | 与当前界面实现一致 |
| 目标用户 | 个人交易员 |
| 使用场景 | 持仓监控、资金视图、加仓与止损测算 |

---

## 1. 产品概述

### 1.1 背景

POSTITON OL 是由桌面端交易分析工具演化而来的**纯前端**网页应用。交易员在单一页面内录入持仓与资金参数，系统自动计算市值、盈亏、风控指标及加仓相关价位，用于盘中决策与复盘。

### 1.2 产品目标

- 提供「资金安全视图」：总市值、本金、欠款、盈利与目标达成率一目了然。
- 提供「持仓监控表」：多标的横向对比，支持快速编辑与风险状态标识。
- 提供「加仓区」：按固定公式生成止损价位。
- 数据仅存于浏览器本地，支持保存、导出、导入、重置。

### 1.3 非目标（本期不做）

- 用户登录与多设备云同步
- 行情 API 自动刷新现价
- 多用户权限与审计日志

## 3. 用户与使用流程

### 3.1 典型流程

1. 打开 `index.html`（或 Vercel 部署地址）。
2. 在全局区填写**本金**、**欠款**、**目标盈利**。
3. 在持仓表中录入**代码**，在「**风控**」内填写现价、成本、预计持仓与持仓数量，并按需填写计划止损额等。
4. 查看自动计算的**市值**、**浮动盈亏**、**状态**；必要时展开「风控」或「加仓」。
5. 点击底部**保存**，或**导出 JSON** 备份。
6. 换设备时通过**导入**恢复数据。

### 3.2 核心操作

| 操作 | 触发方式 | 说明 |
| --- | --- | --- |
| 新增持仓 | 「+ 新交易」 | 新增一行，默认展开风控与加仓区 |
| 编辑字段 | 表格内输入 / 展开区输入 | 失焦后重算并刷新全局总市值 |
| 展开风控 | 「展开风控」 | 显示计划止损额、雷达指标 |
| 展开加仓 | 「加仓」 | 显示加仓区（加仓价格 / 加仓数 / 止损额） |
| 删除持仓 | 「删除」 | 二次确认后移除行 |
| 保存 | 底部「保存」 | 写入 `localStorage` |
| 导出 / 导入 | 底部按钮 | JSON 文件 |
| 重置 | 底部「重置」 | 清空并恢复 4 条空行 |

## 4. 功能模块详述

### 4.1 全局风险脉冲

**展示条件**：任意持仓行的「离场空间」&lt; 2%（状态为「异常」）。

**表现**：

- 顶栏下方红色提示条显示：「风险脉冲：有持仓逼近或跌破止损线，请立即处理。」
- 支持设备振动（`navigator.vibrate`，若可用）。

---

### 4.2 GLOBAL HEADER — 资金安全视图

#### 4.2.1 字段说明

| 字段 | 类型 | 可编辑 | 说明 |
| --- | --- | --- | --- |
| 总市值 | 数字 | 否（只读） | 所有持仓主行「市值」之和（含未合并加仓金额） |
| 本金 | 数字 | 是 | 投入资金 |
| 欠款 | 数字 | 是 | 负债金额 |
| 目标盈利 | 数字 | 是 | 盈利目标 |
| 当前盈利 | 数字 | 否（只读） | 由总市值、本金、欠款推导 |
| 目标达成率 | 百分比 | 否 | 环形进度 + 文案，上限 100% 用于环显示 |
| 最近保存 | 文本 | 否 | 点击「保存」时写入的时间 |

#### 4.2.2 计算公式

```text
单行头寸市值 = 成本 × 持仓数量
（成本或持仓数量缺失时，头寸部分按 0 处理）

未合并加仓金额 = 加仓价格 × 加仓数
（两项均有效时计入；合并到头寸后清空加仓三项，不再重复计入）

主行市值（表格第二列）= 单行头寸市值 + 未合并加仓金额

总市值 = Σ 各主行市值

当前盈利 = 总市值 - 本金 - 欠款
（本金、欠款为空时按 0 处理）

目标达成率 = 当前盈利 / 目标盈利 × 100%
（目标盈利为空或为 0 时，显示 0.00%）
```

#### 4.2.3 交互

- 修改本金、欠款、目标盈利时实时重算当前盈利与达成率。
- 修改任意持仓的「风控」头寸数据（现价、成本、预计持仓、持仓数量等）时，主表总市值联动更新，进而更新当前盈利与达成率。

### 4.3 POSITION MONITOR — 持仓监控表

#### 4.3.1 主表列（从左到右）

| 列名 | 类型 | 可编辑 | 说明 |
| --- | --- | --- | --- |
| 代码 | 股票代码 | 是 | 含操作按钮：加仓 / 风控 / 删 |
| 市值 | 只读 | 否 | 成本 × 持仓数量 + 未合并加仓金额（加仓价格 × 加仓数） |
| 现价 | 只读 | 否 | 数据源见「风控」 |
| 成本 | 只读 | 否 | 数据源见「风控」 |
| 预计持仓 | 只读 | 否 | 预仓数量，数据源见「风控」 |
| 持仓数量 | 只读 | 否 | 数据源见「风控」；也可通过「加仓→合并到头寸」更新 |
| **加仓止损** | 只读 | 否 | 与「加仓」测算一致：(加仓数 × 加仓价格 − 止损额) / 加仓数；未填写加仓项时显示 `--` |
| 浮动盈亏 | 只读 | 否 | (现价 - 成本) × 持仓数量 |
| 状态 | 只读 | 否 | 正常 / 超预仓 / 异常 |

> 主表中现价、成本、预计持仓、持仓数量**在「风控」内编辑**；亦可在「加仓」中点击 **「合并到头寸」**，将加仓结果写回头寸（见 4.3.3）。

> **测试行2**：每条持仓主行下方固定一行，左列「测试行2 · 加仓合计」。列与主表对齐，展示**历次合并 + 当前未合并**的加仓汇总数字：
> - **市值**：总加仓金额（Σ 加仓价格 × 加仓数）
> - **成本**：总止损额（Σ 各笔止损额）
> - **预计持仓**：当前未合并加仓数（加仓区在填写的笔）
> - **持仓数量**：总加仓数（Σ 历次合并 + 当前未合并）
> - **加仓止损**：当前未合并笔的止损价位（公式同加仓区）
>
> 未合并加仓金额另计入主行「市值」与全局「总市值」；合并后该笔进入历史与合计，不再重复计入主行未合并部分。

> **加仓历史行**：每次成功「合并到头寸」后，该笔加仓快照写入 `addHistory`，并在其后追加一行，左列为「加仓1」「加仓2」…（冻结合并当刻数据）。历史行市值仅作明细展示，**已包含在主行头寸市值内**，不再叠加到总市值。

**行内操作**：

- **加仓 / 收起**：展开/收起加仓区
- **风控 / 收起**：展开/收起风控区（头寸 + 雷达）
- **确认**（风控区内）：将头寸与止损字段写入主表并**自动收起**风控区（单击生效，无需点两次）
- **删**：删除当前行

**颜色规则（浮动盈亏）**：

- 盈利 &gt; 0：红色（`red`）
- 亏损 &lt; 0：绿色（`green`）

#### 4.3.2 风控展开区（头寸 + 雷达）

风控区分为四块：

**1）头寸录入（主表数据源）**

| 字段 | 字段键 | 说明 |
| --- | --- | --- |
| 现价 | `currentPrice` | 同步主表「现价」 |
| 成本 | `costPrice` | 同步主表「成本」 |
| 预计持仓 | `plannedPosition` | 同步主表「预计持仓」 |
| 持仓数量 | `position` | 同步主表「持仓数量」 |

**2）止损与当日**

| 字段 | 字段键 | 说明 |
| --- | --- | --- |
| 当日盈亏 | `dayPnl` | 记录用 |
| 计划止损额 | `stopLossAmount` | 用于雷达止损推导 |

**3）加仓测算（预览）**

| 展示项 | 说明 |
| --- | --- |
| 加仓止损价（与主表同列） | 计算公式与加仓区下方一致；与主表「加仓止损」列同步展示 |

**4）持仓状态雷达（自动指标）**

| 指标 | 公式 | 备注 |
| --- | --- | --- |
| 预仓转换成本价 | 若 持仓数量 ≥ 预仓数量：现价×持仓数量÷预仓数量；否则：成本 | 预仓为 0 时不计算 |
| 恢复涨幅 | (成本 - 现价) / 现价 × 100% | 仅当现价 &lt; 成本时计算 |
| 止损价 | 成本 - 计划止损额 / 持仓数量 | 持仓数量为 0 时不计算；若存在历史字段 `execStopPrice` 则优先使用 |
| 离场空间 | (现价 - 止损价) / 现价 × 100% | |

**状态判定**：

```text
若 离场空间 < 2%：
  状态 = 异常（红色脉冲）
否则若 持仓数量 / 预仓数量 > 1：
  状态 = 超预仓（琥珀色）
否则：
  状态 = 正常（绿色）
```

> 合并入账后，头寸与计划止损额变更，本节雷达会按新数据重算。

**「确认」**（风控区底部）：

- 从风控区读取：现价、成本、预计持仓、持仓数量、当日盈亏、计划止损额，格式化后写入该行状态并刷新主表、总市值。
- 成功后自动**收起**该行风控展开区（「加仓」区不受影响）。

#### 4.3.3 加仓区

**模块标题**：加仓  
**副文案**：填写加仓价格、加仓数、止损额；可 **合并到头寸** 写入风控头寸与计划止损额。

**输入字段**：

| 字段 | 字段键 | 说明 |
| --- | --- | --- |
| 加仓价格 | `addPrice` | |
| 加仓数 | `addCount` | 不可为 0 |
| 止损额 | `addStopAmount` | 占位默认取「计划止损额」 |

**输出 — 加仓止损价（止损价位）**：

```text
止损价位 = (加仓数 × 加仓价格 − 止损额) / 加仓数
```

在主表单独列「**加仓止损**」、风控「加仓测算」与加仓卡片内同步展示。

**「合并到头寸」**：

| 写入字段 | 规则 |
| --- | --- |
| `currentPrice` | 设为加仓价格 |
| `position` | `max(0, 原持仓) + 加仓数` |
| `costPrice` | 无旧仓或成本为空：设为加仓价格；否则 `(原成本×原持仓 + 加仓价格×加仓数) / 新持仓` |
| `plannedPosition` | 原预计为空或 0：等于新持仓；否则 `原预计 + 加仓数` |
| `stopLossAmount` | 设为本次加仓的止损额 |
| `addPrice` / `addCount` / `addStopAmount` | 合并成功后清空 |
| `addHistory` | 追加一条快照：`addPrice`、`addCount`、`addStopAmount`、`currentPriceAtMerge`（合并前主表现价），用于主表下方历史行展示 |
| 展开状态 | 合并成功后自动**收起**该行「加仓」与「风控」展开区 |
| 交互 | 「合并到头寸」「确认」为**单击**触发（输入框失焦不会抢先重绘导致需点两次） |

**状态芯片**：加仓数 ≤ 0 → 加仓数无效；无法计算止损价位 → 待输入；否则 → 已生成。

## 5. 数据模型

### 5.1 全局头 `globalHeader`

```json
{
  "totalAssets": "string",
  "costCapital": "string",
  "debtAmount": "string",
  "targetProfit": "string",
  "currentProfit": "string"
}
```

> `totalAssets`、`currentProfit` 由系统计算后写入状态，保存时一并持久化。

### 5.2 持仓行 `rows[]`

```json
{
  "id": "string",
  "symbol": "string",
  "name": "string",
  "position": "string",
  "plannedPosition": "string",
  "currentPrice": "string",
  "costPrice": "string",
  "dayPnl": "string",
  "stopLossAmount": "string",
  "addCount": "string",
  "addPrice": "string",
  "addStopAmount": "string",
  "addHistory": [
    {
      "addPrice": "string",
      "addCount": "string",
      "addStopAmount": "string",
      "currentPriceAtMerge": "string"
    }
  ],
  "execBuyPrice": "string",
  "execDayPosition": "string",
  "execStopAmount": "string",
  "execStopPrice": "string",
  "rrRatio": "string"
}
```

`name` 为历史字段，界面仅展示**代码**（`symbol`）。导入旧 JSON 时若仅有 `name` 且无 `symbol`，会将 `name` 合并到 `symbol` 展示。

后四个 `exec*` 与 `rrRatio` 为历史字段，界面已不再展示，导入旧数据时仍保留，不影响加仓模块。历史字段 `addHighPrice` 若存在于旧 JSON 中将被忽略。

### 5.3 根状态

```json
{
  "globalHeader": { },
  "rows": [ ],
  "updatedAt": "string | --"
}
```

### 5.4 本地存储

| 项 | 值 |
| --- | --- |
| Key | `postiton_ol_html_state_v1` |
| 介质 | `localStorage` |
| 导出文件名 | `postiton-ol-data.json` |

**初始化**：无缓存时默认 4 条空持仓行。

## 6. 交互与体验要求

### 6.1 布局

- 页面最大宽度 **430px**（iPhone 15 逻辑宽度），整体居中。
- **持仓监控表**采用紧凑标准：8 列按比例分配宽度，**无横向滚动**，一屏内展示全部列。
- 表头与数据字号约为常规版的 **1/3**（表头 8px、数据 7px、代码 9px），行高约 34px。
- 列宽比例：`1.55 : 0.82 : 0.72 : 0.72 : 0.88 : 0.82 : 0.9 : 0.68`（对应 8 列）。
- 底部四按钮固定于视口底部，最大宽度与页面一致，适配 `safe-area-inset`。

### 6.2 视觉

- 深色主题（iOS 风格）：紫青渐变背景、卡片半透明、等宽数字字体。
- 风险：红色脉冲动画；超预仓：琥珀色；正常：绿色。

### 6.3 输入

- 数字字段使用 `type="number"`、`inputmode="decimal"`。
- 编辑中若光标位于全局可编辑字段，渲染时不覆盖该输入框内容，避免打断输入。

### 6.4 空值与异常

- 无法计算时显示 `--`。
- 除法依赖项为 0 或缺失时，对应结果为 `null` → 显示 `--`。
- 无效数字（非有限数）按空值处理。

## 8. 验收标准

### 8.1 全局

- [ ] 总市值等于所有有效行「成本×持仓数量」之和。
- [ ] 当前盈利 = 总市值 - 本金 - 欠款。
- [ ] 目标达成率随目标盈利、当前盈利正确变化。
- [ ] 总市值、当前盈利不可手动编辑。

### 8.2 持仓表

- [ ] 主表列显示正确（含「加仓止损」），市值列在代码列后。
- [ ] 主表「现价、成本、预计持仓、持仓数量」为只读；「加仓止损」来自加仓测算，未填加仓项时为 `--`。
- [ ] 风控区「确认」写入主表并自动收起风控区。
- [ ] 「合并到头寸」后头寸与计划止损额按 PRD 更新。
- [ ] 「合并到头寸」后会在主数据行下方追加「加仓n」明细行，列与主表一致。
- [ ] 浮动盈亏与状态规则符合公式。
- [ ] 离场空间 &lt; 2% 时出现顶栏风险脉冲。

### 8.3 加仓

- [ ] 输入加仓价格、加仓数、止损额后，主表「加仓止损」与加仓区止损价位实时一致。
- [ ] 「合并到头寸」写入加权成本、现价、持仓、预计持仓、计划止损额，并清空加仓三项；成功后该行「加仓」「风控」均自动收起。
- [ ] 加仓数为 0 或负数时状态为「加仓数无效」。

### 8.4 数据

- [ ] 保存后刷新页面数据仍在。
- [ ] 导出 JSON 再导入可完整恢复。
- [ ] 重置后恢复 4 条空行且全局字段清空。
